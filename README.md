# ChronoLake：面向可观测数据的全链路流式加工与治理平台

## 一句话定位

ChronoLake 是一套面向**高基数、大规模、高复杂度**可观测数据场景的端到端解决方案。它以**数仓思维**管理可观测数据，把"数据加工、治理、探索、巡检、可视化"整合在同一条链路上：基于 **SQL 语法与维表**提供自由开放的计算表达能力，基于 **CodeGen、向量化、零装箱**的高性能流式引擎把高额的计算成本降下来；在此之上，以**多 Agent 专家体系**承载领域经验，由**栈式状态机执行引擎**保证 Agent 的可控与可恢复，并通过**全链路 Trace**让每一次 AI 分析都可追溯、可排障。

> 一句话买点：**数据即资产**——用一段 SQL 表达一条派生指标、一个 SLI、一条告警规则，它们走同一编译路径、共享同一份维表，并沉淀为可治理、可溯源的数据资产；再让**专家 Agent 基于这些可信数据辅助分析，且每一步都留痕**。

---

## 一、为什么需要 ChronoLake

可观测数据正在从"监控指标"演进为"企业级数据资产"。当指标基数攀升至百万、千万量级，业务对数据加工的两个诉求同时被放大——**想算什么**，和**花多少算力去算**。传统的监控与流计算工具恰好在这两点上各自失守：

- **表达被工具圈死**：监控系统的 Recording Rule、预聚合模板只能覆盖有限的固定模式；业务真正需要的跨维表关联、复合派生、多层 SLI，要么表达不出来，要么逼着用户为每类场景再学一套 DSL、再维护一套胶水代码。数据加工的自由度，被工具的预定义能力封了顶。
- **算力成本随规模失控**：海量时序流上，解释执行的字段开销、逐行装箱的对象分配、每任务一个独立作业的资源隔离，让计算成本随数据规模线性上涨——而且其中相当一部分算力花在了框架自身上，而不是数据上。规模越大，这份"看不见的账单"越重。
- **治理缺位**：数据没有标准、没有血缘、没有质量约束，难以沉淀为可信赖的资产，更无法支撑 AI 分析。
- **AI 用不稳、管不住、查不清**：单个"万能助手"既缺领域经验，又难以约束权限与成本；一旦多个模型调用、工具调用、子任务交织在一起，出了问题既说不清"它为什么这么答"，也无从定位慢在哪、错在哪。

ChronoLake 对前两个问题的回答构成它的核心叙事——**基于灵活的 SQL 语法提供自由开放的计算表达能力，基于高性能的流数据处理能力把高额的计算成本降下来**：业务用一段标准 SQL 表达任意加工逻辑（窗口聚合、派生指标、维表 JOIN），引擎将其编译为原生代码、列式向量化执行、并由同一 Runtime 承载全部任务——让每一份算力都花在数据上，而不是框架上。在此基础上，再以数仓思路完成治理、血缘与全链路闭环；并把"专家经验"沉淀为可扩展的多 Agent 体系，用栈式状态机把 AI 执行变成可约束、可挂起、可追溯的工程对象。

## 二、核心能力

### 1. SQL 驱动的灵活数据加工

ChronoLake 以 **SQL API** 作为数据加工的统一入口，配合**维表（Dim）**的关联能力，让用户用熟悉的声明式语法表达任意复杂的加工逻辑：窗口聚合、降采样、派生指标、复合 SLI、跨维表 JOIN 等。SQL 即 API，无需为每类场景维护第二套 DSL，业务定制能力高度灵活。

### 2. 高性能流式数据引擎

底层引擎面向高基数、大规模场景做了深度优化：

- **CodeGen**：将 SQL 编译为低开销的本地执行代码，消除解释执行的运行时损耗。
- **向量化**：以批量化方式处理数据，充分利用现代 CPU 的并行与缓存能力。
- **零装箱（Zero-Boxing）**：在热路径上避免对象装箱与额外内存分配，降低 GC 压力。
- **零拷贝（Zero-Copy）**：数据在接入、加工与输出链路上尽量原地传递，避免冗余的内存复制与序列化开销，进一步压低延迟、提升吞吐。

这些技术叠加，使 ChronoLake 在同等资源下能承载更高的吞吐与更低的延迟，**数据规模越大，流式处理的性能优势越明显**。

### 3. 完整的数据治理与血缘

ChronoLake 内建数据治理体系：通过统一的元模型管理流（Stream）、维表（Dim）、加工管线（Pipeline）与告警规则（AlertRule），自动产出**数据血缘（Lineage）**。任意一条派生指标都能向上追溯到其源头数据与加工逻辑，实现完整的**数据溯源**——这是问题排查、影响分析与合规审计的基础。

### 4. 全链路可观测闭环

ChronoLake 不是单点工具，而是一套覆盖全链路的可观测解决方案：

```
数据加工  →  数据治理  →  数据探索  →  自动巡检  →  Dashboard 可视化  →  专家 Agent 辅助分析（全程 Trace）
```

从原始数据接入、SQL 加工、质量治理，到自动巡检、可视化展现与专家 Agent 辅助分析，所有环节在同一平台内闭环协同，避免了多系统拼接带来的割裂与运维负担。

### 5. 基于多 Agent 的专家能力扩展

ChronoLake 不把 AI 做成"一个会调工具的万能助手"，而是做成**可编排、可管控、可扩展的多 Agent 专家体系**：每位专家只负责一类问题，把领域经验沉淀进自己的"名片"，由 Router 按需调度。

```
用户提问
  └─ Router Agent（理解诉求，只看各专家的名片，不碰业务工具）
       ├─ 业务分析 Agent      沿实体层级下钻 / 上卷 / 对比，逐层定位
       ├─ 大盘助手            按描述配置监控大盘，先建草稿，满意再发布
       ├─ 语义建模评审 Agent  以架构师视角评审实体、维表与引用绑定（只读）
       ├─ 运维建模助手        问清场景 → 出方案 → 逐项试算并落库
       ├─ Agent 创建助手      通过追问帮你设计并创建自己的 Agent，只存草稿
       └─ …… 你自己的专家 Agent
```

- **新增一位专家 = 新增一张 AgentCard，不改代码、不重启**：名片固定为"路由名片（一句话职责、适用 / 不适用场景、示例）+ 角色与工作流程 + 行为准则 + 约束 + 运行预算 + Tool 与子 Agent 绑定"。路由只看名片，因此"不适用场景"与"适用场景"同等重要，是避免误投的主要手段。
- **Agent 即 Tool**：对模型而言，委派一个专家就是一次 tool call。专家可以再委派其他专家，同一步里的多个委派并发执行；依赖关系通过"跨步"表达，框架不做 DAG 编排。
- **专家经验可沉淀、可版本化**：名片支持草稿、发布、版本历史与回滚，保存与发布都带乐观并发控制；停用即下线。管理员维护平台级专家，组织与个人可定制**企业级、个人级** Agent；Agent 的受众（成员 / 域管理员 / 组织管理员）决定谁能使用它。
- **用对话创建专家**：内置的"Agent 创建助手"会通过追问补全职责、适用与不适用场景、工作流程、约束与工具，并在试算校验后**只保存为草稿**；你到控制台预览、调试，满意后自行发布。它也能读取你已有的 Agent，给出"改前 → 改后"对照后再优化。发布、停用、删除不在它的能力范围内——这条边界由工具保证，而不是靠提示词。
- **能力不继承，边界在代码里**：专家只能使用自己名片绑定的 Tool，委派不扩权；Tool 按只读 / 修改 / 危险分级，租户 Agent 只能绑定向租户开放的 Tool；调用透传用户凭证，由 API 自身鉴权；修改类操作在静默点合批，由用户**批量二次确认**。
- **Agent 控制台**：面向所有组织成员开放，按角色与归属收窄——Agent 管理与名片编辑、绑定面板、调试台与运行记录。

> 能力边界：专家以名片与 Tool 绑定为边界，做**辅助分析与建模**，不自动执行未经确认的修改；不提供 Agent 自动生成 / 自我进化，也不提供 Agent 之间的自由协商。

### 6. 基于栈式状态机的 Agent 执行引擎

多 Agent 协作的难点不在"调用模型"，而在**调用嵌套之后仍然可控**：深度、并发、预算、权限、挂起与追溯。ChronoLake 的 Agent 运行时用一台**栈式状态机**统一解决——**Agent 是栈帧，每个操作是一条指令**。

```
Session（一个对话窗口，跨多次提问）
 └─ Turn（一次提问 → 一棵调用树，状态机整体驱动）
      └─ Frame(router)
           ├─ Frame(业务分析 Agent) ─ Frame(子 Agent) …   ← 委派 = 开帧；返回 = 收口
           └─ Frame(大盘助手)
```

- **三层状态，一棵调用树**：会话（`Session`）、单次提问（`Turn`）、Agent 一次执行（`Frame`）各有标识与生命周期。委派子 Agent 是向父帧追加子帧，子帧收口后把结论回填父帧；帧只追加、不删除。
- **栈在堆上**：调用深度不受 JVM 调用栈限制，只受显式守卫约束——环检测、深度、帧数、同步扇出、重复调用次数，以及每个 Agent 自己的步数 / Token / 时间预算。
- **决策与副作用分离，单写者串行折叠**：下一步怎么走是只读的决策，LLM 与 HTTP 调用是显式的外部 effect，可跨帧并发；而所有状态变更只在一个线程内串行折叠，并发不引入共享可变状态，也就不需要锁。
- **帧边界即信息边界**：帧与帧之间只有两条通道——开帧时的任务简报、收口后的结论。祖先、兄弟、子孙的对话记录不会进入任何模型上下文，只用于审计与回放，既控制上下文膨胀，也避免信息串扰。
- **栈即快照，可挂起恢复**：需要用户确认修改时，整个 Turn 在静默点落盘挂起；确认后原样重建继续执行，预算不重置，恢复前先校验状态不变量。凭证只存在内存，不进快照与日志；凭证失效则直接终止并提示重新登录。
- **写入受控**：同一静默点上所有被拦截的修改类调用合并成一个批次，由用户逐项确认；批次内各项相互独立，某项失败不影响其余项，参数以挂起时持久化的内容为准并校验哈希。
- **追问不是挂起**：Agent 需要补充信息时，本次提问以"需要补充"结束，下一次提问携带摘要衔接——追问与写入确认是两种不同的机制，状态机各自处理。
- **事件流可补发**：对话通过 SSE 推送，事件序号即状态机迁移序号；连接中断后可按序号补发，不丢过程。

> 说明：挂起 / 恢复服务于"写入确认"，当前不宣称进程崩溃后的自动恢复。

### 7. AI 可观测：每一次 Agent 运行都可追溯、可排障

ChronoLake 用可观测的方式观测 AI 本身。**一次提问对应一条 Trace，一个 Agent 帧对应一列，一条指令对应一个 Span**——栈式状态机的调用树直接就是调用链路。

| 栈式状态机 | Trace |
|---|---|
| 指令（LLM 调用 / Tool 调用 / 委派 / 确认） | **Span** |
| 栈帧（一个 Agent 的一次执行） | **链路列** |
| Turn（一次提问） | **Trace** |

- **看清模型每一步**：每次 LLM 调用记录完整入参（系统提示、运行时上下文与消息序列）、出参、耗时、首 Token 时延，以及输入 / 输出 / 缓存 Token；每次 Tool 调用记录输入、原始输出与模型实际看到的内容，以及来源、风险级别与 HTTP 状态。
- **被拦截的调用也留痕**：参数校验失败、委派守卫拒绝等没有真正执行的调用，同样生成 Span 并标注 `BLOCKED`，能看到"模型想做什么、为什么被拦下"。
- **两种视图**：**链路列**从左往右逐列下钻（每列是一个 Agent：输入任务 → LLM / Tool / 子 Agent / 确认 → 返回，并发委派会标出"并行 ×N"）；**瀑布图**把所有 Span 放在同一条时间轴上，展示并发、关键路径与耗时构成，直接回答"慢在哪里"。点击任一节点可在右侧查看完整载荷。
- **运行记录**：按时间、用户、组织、状态、耗时、Token 筛选所有请求；成员只看自己，组织管理员看本组织，平台管理员看全平台。
- **与现有体系打通**：每条 Trace 有独立的 W3C 兼容 `traceId`，透传到下游 HTTP / MCP 工具，并写入日志 MDC，可在日志里按 `traceId` 检索；用户反馈问题时附上 Trace ID 即可定位。
- **对运行零影响**：留痕走独立的异步通道，队列满了丢弃并计数、绝不阻塞 Agent 的驱动线程；LLM 入参按消息内容寻址去重，避免多轮调用造成存储 O(n²) 膨胀。
- **数据安全**：载荷落库前按敏感键名脱敏（可追加自定义词表）、超长截断并标记；数据敏感的部署可切换为只保存 Span 骨架与摘要；跟踪数据默认保留 14 天，超期按 Turn 整批清理。

> 说明：跟踪页为只读排障视图，不做"重放执行"和费用换算，暂不提供 OpenTelemetry 导出（数据模型按 trace / span 语义设计，后续可直接映射）。

### 8. 数据、语义与 AI 的正向循环

数据治理让数据**标准化、结构化、可信赖**，为专家 Agent 提供高质量的事实基础；语义模型把"数据长什么样"补全为"它属于谁、和谁相关"，让 Agent 读得懂；Agent 基于真实数据与领域语义辅助检索、分析与建模，并通过建模助手反哺语义与治理，Trace 则让这一循环**可观测、可复盘**。形成"治理喂养 AI、AI 反哺治理、Trace 保障可信"的正向循环。

## 三、差异化定位：与同类产品的对比

ChronoLake 的价值，需要放在它与现有生态的差异中才能看清。

### 对比 Prometheus —— 应用场景不同

Prometheus 是优秀的监控与告警系统，定位于指标采集与短期存储。ChronoLake 的出发点完全不同：

- **数仓思路 vs 监控思路**：ChronoLake 把可观测数据视为**资产**，强调数据的**管控与治理**，而非单纯的指标采集与查询。
- **SQL 表达力 vs PromQL**：基于 SQL 的强大表达能力，ChronoLake 提供远超 Recording Rule 的灵活加工能力——窗口、JOIN、CTE、跨维表关联皆可表达。

两者并非竞争，而是定位不同层次的问题：Prometheus 关注"看指标"，ChronoLake 关注"把数据治理成资产并灵活加工"。

### 对比 Flink SQL —— 同一 Runtime、热更新、热部署

Flink SQL 是强大的流计算框架，但采用**单一任务模式**：每个 SQL 任务对应一个独立作业，部署重、运维成本高。ChronoLake 在工程形态上做了根本性的差异化：

- **同一 Runtime 运行大量 SQL 任务**：无需为每个任务拉起独立作业，资源利用率与运维效率显著提升。
- **SQL 热更新、热部署**：可对数据拓扑中**任意一个计算节点**的 SQL 任务进行热更新与热部署，无需停机或重启整条链路——这是单一任务模式的 Flink SQL 不具备的能力。

| 维度 | ChronoLake | Prometheus | Flink SQL |
|---|:---:|:---:|:---:|
| 核心定位 | 数仓式可观测加工与治理 | 指标监控与告警 | 通用流计算 |
| 加工表达力 | 完整 SQL + 维表 JOIN | PromQL / Recording Rule | 完整 SQL |
| 多任务运行 | 同一 Runtime 承载大量任务 | — | 单任务独立作业 |
| 热更新 / 热部署 | ✅ 节点级热更新 | — | ❌ |
| 数据血缘 / 溯源 | ✅ 完整血缘 | ❌ | ⚠️ 有限 |
| 数据治理 | ✅ 内建 | ❌ | ❌ |
| 全链路闭环 | ✅ 加工→巡检→可视化 | ⚠️ 监控告警 | ❌ 仅计算 |

### 对比单体 AI 助手 —— 专家协作、受控执行、全程可追溯

常见的 AI 助手形态是"一段系统提示词 + 一组工具"。它起步快，但随着场景增多，提示词越写越长、工具权限越开越大、出了问题也越来越难解释。ChronoLake 在 Agent 的工程形态上做了不同的取舍：

| 维度 | 单体 AI 助手 | ChronoLake 多 Agent 体系 |
|---|---|---|
| 能力扩展 | 不断堆叠提示词与工具，互相干扰 | 一位专家一张名片，新增即扩展，Router 按名片调度 |
| 领域经验 | 散落在提示词里，难以复用与演进 | 沉淀为版本化的 AgentCard：可发布、回滚、停用 |
| 权限边界 | 往往依赖提示词约束 | 工具绑定即边界，委派不扩权，凭证透传、由 API 自身鉴权 |
| 修改类操作 | 模型一步到位 | 静默点合批，用户批量二次确认 |
| 执行模型 | 线性对话循环，嵌套调用难以约束 | 栈式状态机：调用树、预算与守卫、挂起 / 恢复 |
| 问题排查 | 只能翻日志 | 一次请求一条 Trace：链路列 + 瀑布图，下钻到每次 LLM 与 Tool 调用 |

## 四、灵活的交付形态

ChronoLake 同时支持两种部署模式，适配不同规模与合规要求：

- **云服务**：以 SaaS 形态提供全套数据服务，开箱即用，免运维。
- **私有化部署**：在客户自有环境内完整落地，满足数据合规与安全要求。

得益于高性能流式引擎，**数据规模越大，私有化场景下流式处理的性能与成本优势越能凸显**。

## 五、典型适用场景

- **高基数指标加工**：百万/千万级时间线的实时聚合、降采样与派生指标计算。
- **复杂 SLI / SLO 体系**：跨维表关联、多层派生的复合服务质量指标体系。
- **统一可观测平台**：需要把加工、治理、巡检、可视化整合到一个平台的中大型团队。
- **数据资产化与 AI 分析**：希望将可观测数据标准化、资产化，并以专家 Agent 辅助分析与排障的场景。
- **沉淀运维专家经验**：把资深运维、SRE 的分析套路沉淀为可复用、可版本化的专家 Agent，让团队成员按需调用，并支持自建个人 Agent。
- **需要审计与排障的 AI 应用**：对 AI 的权限、写入确认、调用链路与耗时有明确要求，需要"每一步都说得清"的企业场景。

---

## 结语

ChronoLake 用**数仓的思路**重新定义可观测数据处理：以 SQL 为表达力、以治理为基础、以血缘为保障，再以**多 Agent 专家体系**承载领域经验、以**栈式状态机**约束 AI 的执行、以**全链路 Trace**保障每一次分析可追溯，提供从加工到分析的全链路闭环。它不与监控系统或通用流计算框架同质化竞争，而是在**高基数、大规模、高复杂度**的可观测场景里，提供一套更灵活、更高性能、更可治理的完整解决方案——让数据真正成为可信赖、可复用、可被 AI 驱动且可被追溯的企业资产。
